### Features

- **Point the AI at items with @, and complete tags in every AI box.** In the chat, every Draft with AI box and the Pack builder, type **@** and a few letters to pick a wildcard, any other module or a bundle. It goes in as a mention of that exact item, the assistant is handed what the item is with your message, and your message shows it as a chip, so "add more options to @Hairstyle" needs no search and can't land on a look-alike. **$** completes variables, and with tag and model completion on, a few letters offer Danbooru tags, LoRAs and embeddings like in the editors.
- **Variables are coloured text, not green chips.** Every `$variable` in combine, derivation, negative and template text is now written as plain text in its own colour (the same colour everywhere), so it edits like any other word. Hovering it still shows which module writes it. Nested `@` references keep their chips.
- **Draft wildcard options with AI, using a model you choose.** A new **Settings → AI assistant** page (off by default) connects the manager to Ollama, LM Studio, llama.cpp or any OpenAI-compatible server on your PC, or to the Claude or OpenAI API with your own key. Pick the model from the server's list, press **Test connection**, and set how long a local model stays loaded so it hands the GPU back to ComfyUI. Then the **AI** button in the wildcard editor writes the number of options you ask for in the style of the ones already there, reusing your tags. You see the list first, untick what you don't want, and **Add** puts the rest in the editor like pasted options; nothing is saved until you press Save. Options can use `{a|b}` picks and point at other wildcards by name (`@{Colors:warm}`); the assistant turns the name into a real reference and checks the tag filter against that wildcard's tags. Duplicates, options that read a `$variable`, and references to a wildcard or tag you don't have (or back to the wildcard itself) are left out and listed. The same panel's other tabs edit what is already there: **Remove** finds options matching what you describe, **Rewrite** changes their wording, **Retag** sets their tags and **Weights** makes them rarer or more common, on every option or just the selected ones. Each shows a before/after list to tick through before anything changes. The fixed values, combine and template editors have an **AI** button too: it writes a style preset with its negatives, a combine that joins your variables, or the Assembler prompt with a standing negative and `$negatives`, and warns about any variable nothing sets (a template never gets `{a|b}`, which the seedless Assembler would print as is). The derivation and constraint editors have one as well: describe the rules ("when $class is mage, set $title to Archmage") and it writes them with your library's variables, options and tags, in plain words to review before **Add** or **Apply**. Derivation rules come with warnings when they read a variable nothing sets or test for an option the wildcard doesn't have; constraint rules become matrix cells for tag pairs and exceptions for option pairs, and say when they replace a rule the pair already had, with a **Preview** of each option's chances before and after. **Describe** on every editor's Identity card writes a description and tags (reusing your library's tags), and every AI request now includes the item's name, description and tags so the model knows what it's for. Select modules or bundles in a library list and **Organize with AI** suggests a category, tags to add or remove and a Safe/NSFW rating for each, reusing your categories and tags; click a chip to leave a change out, **Apply** saves with Undo. The **AI** button in the top bar opens a chat: ask about your library and the assistant searches and reads your items to answer, or ask for a change and it proposes it as a card: create a wildcard (with tag groups, negatives, an empty option, a fallback and references to other wildcards, or a vocabulary wildcard with no variable), fixed values, a combine, a derivation, a constraint, a prompt template or a bundle (put in running order, with per-use settings like "pick 2-3", a tag filter, "no empty", "hold" and "internal"); add options or rules; remove, rewrite, retag or re-weight options, set their negatives, the fallback, the empty option's weight or tag groups; replace or remove derivation rules, change a constraint's rules and reach, change fixed values, a combine, a template or a bundle's items; change an item's description, tags, category or rating; or open an editor, a docs page or a Settings section. It can run a stack on the real engine before answering (each variable's top values, options never picked, warnings, sample prompts) and, with its own proposals swapped in, say what they change. In the Test Runner, a bar above the results asks it to **Explain this run**, **Fix the warnings** or say **Why do I never get…** an option. It sees the page you're on: the item in the open editor as it is (unsaved changes included), a list's filters and selection, the Test Runner's last run, the Pack builder's plan. A change to the item open in an editor goes into the editor and Save keeps it; other changes are saved only when you press **Apply** on the card, and **Undo** puts them back. It also answers questions about Wildcard Pipeline from the built-in docs, naming the page it used, and **Ask the assistant** on any docs page explains the page (or the part you selected) in simpler words. **Pack builder** (in the sidebar) makes a whole pack from one description: it plans the wildcards (including vocabulary wildcards other options draw from), fixed values, derivations, combines, constraints and a template, per-use settings for the bundle, and inputs the pack reads but you set through a WP Context Injector, and may ask a few questions; you answer, remove items or type changes; then it builds each item, runs the pack 200 seeds on the engine, rebuilds anything that fails with the problem as a note, and shows sample prompts. **Install** adds everything with a bundle, tagged with the pack's name, says how to wire it on the canvas, and one **Undo** removes it. When an answer is close but not right, type a follow-up ("darker", "keep the first three") and press **Refine**: the model revises its last answer, knowing what you asked before and what you unticked, instead of starting over. **Try again** asks for another take, the arrows flip back to earlier answers, and **Start over** drops the conversation. Each provider keeps its own address, model and key, so switching between them doesn't ask for the key again. The key stays on ComfyUI's side and is never sent back to the browser. The page suggests uncensored local models with Ollama and Hugging Face links, in two groups: fine-tunes trained on creative writing (NSFW included) for drafting, and abliterated models that follow instructions best for organizing and building packs. The assistant sizes itself to your model: **Model size** (automatic from the model's name) gives small models shorter instructions and steadier settings, **Most context to use** makes Ollama load enough context for each request (its small default used to cut the instructions off), and **Test connection** warns when LM Studio or llama.cpp loaded the model with too little context. The chat plans before acting, runs its own proposed module changes on the engine before answering, can propose items that depend on each other in one answer, asks again once when an answer comes back garbled, and is told once to act when it asks "should I go ahead?" or meets your "yes" by asking again. It no longer loses your first question after a search (it used to answer with a generic greeting) or repeats the same search until it runs out of steps: each step's results go back with your question, a repeated call is refused, and the last step must answer. Ask it for a whole new pack and its card's **Plan it** hands the description to the Pack builder and starts the plan. The chat's search reads what items hold (option texts, values, rules), ranks the hits and widens broad subjects, so "what do I have for characters" finds hair, eye and outfit wildcards; replies render bold, lists and code, every item it names is a chip that opens it, prompt syntax is coloured like in the editors ($variables, `{a|b}` picks, `@{…}` references, LoRAs, #tags), and "Tip:" / "Warning:" lines stand out. The **Settings → AI assistant** page now uses the full width: provider buttons marked Local or Cloud, compact fields, and side cards for where your data goes and suggested models. **Most context to use** and **Unload the model after** have presets (4k-128k, right away to 1 hour) with Custom for any number. **Test connection** now warns below 16k of context (it used to stay quiet at 8k, which the chat outgrows after a few turns). The Pack builder reads your library's conventions (tags or sentences, tags, variables, standing negatives), reuses wildcards you already have (marked **yours**), can start from a sample prompt you like, and shows a **Plan review** before building (variables nothing sets, constraint tags neither wildcard lists, loops, picks nothing links), with **Review with AI** and **Fix these in the plan**. Building puts rules after what they read, tells each wildcard which rules use it, retries a failed item with the error, rebuilds one that doesn't fit, and flags options that never come up or take most of the picks. After a wildcard pack import, **Tag and connect with AI** opens the chat to tag the new lists, link them with constraints, bundle them and test the result. No schema change.
- **The Pack builder asks better questions and lets you shape the plan.** Questions can take several answers, have an **Other** box for your own and **Decide for me**, and once answered they are never asked again: they show as chips under **You decided**, next to what the model assumed, and each can be changed. **Pack settings** set whether the pack reuses your library, follows its style or builds everything new, how negatives are written (a standing negative plus negatives on options that need them, template only, or none), one bundle or a sub-bundle per section, tags or natural phrases, the rating and the options per wildcard. Every item can be edited by hand, changed by the AI on its own, removed or added, and your edits stay when the plan updates. Plans hold up to 60 items (was 20), grouped by section, each with its id reserved up front so references, nested wildcards and linked constraints can point at items not built yet. The review runs as you edit, with **Apply** and **Dismiss** per finding and **Fix with AI** for the ticked ones. Reference images (pasted, dropped or picked) go to a model that sees them. With web search set up, the planner asks to search when real-world facts would help; nothing runs until you allow it. A stuck item stops after 4 minutes, and **Skip this item** moves on right away. The plan page no longer spills out of its column on long names and tags.
- **Extend a bundle with AI, and split one into sub-bundles.** The bundle editor's **Extend with AI** opens the Pack builder on the bundle: its modules and variables are known, its sub-bundles are the sections, and install adds the new modules where they belong and updates the bundle in one undoable step. **Make sub-bundles** groups a bundle's children into sub-bundles by name, by hand or with **Suggest with AI**, which only groups neighbours so the bundle runs in the same order.
- **Draft with AI takes reference images and can ask to search the web.** Every Draft with AI panel (wildcards, rules, fixed values, combines, templates) takes up to 4 reference images when the model can see them. With web search set up, the wildcard and text panels may ask to search for facts they don't know; the answer shows anyway, and **Search and refine** runs the searches and revises it.
- **See what a constraint does before you run it.** The constraint editor has a new **Preview** card: one row per source option, one column per target option, and in each cell the chance that target option is picked, counting the target's weights, the matrix and the exceptions. Ruled-out options show a dash, a row that would leave the target empty says **nothing left**, and **fallback** marks where the target's fallback option stands in.
- **Pick which images go on to the upscaler with WP Image Filter.** Put the new node between your first KSampler and the upscaler. When a run reaches it, a picker opens with every image (grouped by frame when a Context Loop made them). Click the ones you want, click the frame around an image (or **Zoom & refine**, or **Space**) to look closer, and **Enter** to send them on. Only the picked images continue, and their latent, masks, positive and negative conditioning, prompt texts and Context come along with them, so the upscaler gets each image's own prompt. Two **extra** slots carry anything else that should follow the picks. **Keep all** lets everything through and **Stop branch** stops what comes after the node without failing the run. On the node you choose whether it pauses every run, reuses your last picks, or lets everything pass, a timeout, and whether picks keep their batches or go on one image per item. The picker can be tucked away to look at the canvas and keeps your picks until you open it again. While it waits, a short chime plays and the tab title starts with **● Pick images**, so you notice from another tab (new settings: **Image Filter sound**, on by default, and **Image Filter desktop notification**, off by default). No schema change.
- **Refine your picks before they reach the upscaler.** In the Image Filter zoom, a **Refine** panel lets you edit the frame's positive and negative prompt and paint a mask on the image. An edited prompt replaces the text output, and with a CLIP wired into the node's new optional **clip** input the conditioning is re-encoded to match. A painted mask goes to the **masks** output, so an inpainting upscaler can work on just that area.
- **The Image Filter picker knows your Context Loop.** Frames are labelled with the options your sweep pinned (hover for the seed and prompt), a sweep opens as a grid where you choose which wildcards go on rows and columns and the rest split into small grids (click a row, column or group name to pick all of it), **C** compares two images with a slider, **Fit** (**F**) makes a few images fill the picker, **I** adds a Details panel to the zoom (the frame's values, its other images, and each value marked in the prompt), and the picker opens zoomed if you left it zoomed. **Send to Loop** writes your picks back to the loop, locking the kept frames' seeds and bypassing the rest, so the next run repeats only what you liked.
- **See what the AI is doing while it works.** Every AI wait (Draft with AI panels, the Pack builder, the chat) now shows one line with our sparkles animated, a changing word and the time so far, like "Shuffling… 1m 05s". Every few words, and whenever it changes, the word is what the model is actually doing: reading the prompt, thinking, or writing with about how many tokens so far. The same line sits in the top bar on every page while a request runs. It used to be a spinner and "local models can take a minute" with no way to tell whether anything was happening.
- **The Pack builder shows what changed and waits for the web search.** After an update each plan item says whether it is **new** or what changed, and a line above the plan sums up the round (removed items too). With reference images, **From your images** lists what the planner took from them, so you can see it read them. A web search the planner asks for now sits at the top and holds answers, plan updates and Build until you allow or skip it; it used to sit under the questions and was lost once you answered them. A meter under your request shows how much of the model's context the last plan took. Clicking a decision or a guess now lights up **Change the plan** and says what was added there, and the decision stays listed (crossed out) until the plan updates instead of disappearing. Plans branch: updating an earlier plan adds a new one marked "from plan 1" and keeps the others. Your own answers grow as you type and can be resized, and long decisions and guesses wrap cleanly. Pack settings are now their own step between Describe and Plan, with a line saying what each choice does, and they are kept for the next pack. Reference images are numbered so you can say "image 2", and they go with an update only when they change, when the update mentions them, or when you tick **Show the images again** (each costs about 1,000 tokens a request). **Start over** is a proper button.
- **Explain any text with AI, and a chat that fits the page.** Select text anywhere in the manager (docs, chat replies, warnings, test results) and a small bar appears above it: **Explain** asks the chat to explain it in simpler words, **Ask** quotes it in the message box for your own question, and `Ctrl+Shift+X` explains it without the bar. It stays out of text boxes and editors and leaves the browser's right-click menu alone; turn it off under **Settings › AI assistant › Show Explain on selected text**. A new chat's starter questions now fit the page and your library (constraint questions on Constraints, your own wildcard count on Wildcards, your biggest category on the home page, improvements in an editor) and include **What can you do?**. The assistant can react to your message with an emoji, and a message that is only thanks or praise gets a reaction right away without a model call. While it works, the status word now crossfades into the next one in place, with a light shimmer running across it, instead of blinking out; the box eases to the new word's width.
- **Edit negatives on the node and in bundles.** A fixed values module on a Context node, or inside the bundle editor, now shows each value's negative under it: change it for that use only, clear it, or give a row you added its own. A combine's negative sits under its template the same way. Each has a reset button that brings back the library's negative. Wildcard option negatives stay in the library editor. (Uses schema v8, like other negatives.)
- **The chat can change the Test Runner's stack instead of replacing it.** Ask it to add a module to the run or take one out, and it edits the stack that is open (a saved scenario too), keeping your seeds and pins. Testing a constraint brings its source and target wildcards along in the right order, since a constraint alone does nothing.
- **Model suggestions per provider.** **Settings › AI assistant › Suggested models** now lists picks for the provider you chose (Claude models for Claude, GPT-6 Luna for OpenAI, unmoderated open models for OpenRouter, uncensored models for a local server), in a shorter list that marks which ones were tested with Wildcard Pipeline and which come from benchmarks and community reports. OpenRouter picks link to their page for the current price.
- **A new loading mark across the manager.** Spinners and plain "Loading…" text now show the logo with its two rings sliding apart and back while the star turns: busy buttons, the database and maintenance panels, the template editor, tags and impact scans, the Community tab while it opens, and a splash while the manager itself loads. The AI keeps its own working line.

- **The assistant knows your nodes, canvas, tags and LoRAs.** The chat, Draft with AI and the Pack builder now know how the WP Context Loop works (`$iteration`, `$iteration_total`, sweeps, hold), what a WP Context Injector row brings in (a LoRA's trigger words, any socket value), WP Model Info's `$model_family`, `$model_variant` and `$model_name`, and the Image Filter. With the canvas open in another tab, they also know which variables it sets at run time, so a pack reading them isn't flagged. While their autocomplete is on, the chat can look up your downloaded Danbooru tag list (real spellings, post counts, whether a tag exists), your LoRA files and your embeddings; the Pack builder gives the planner your matching LoRAs, gives tag-style wildcards the tags your list knows, and notes built options whose tags aren't in your list. Every screenshot and diagram in the docs now has a written description, so the assistant can explain them (screen readers read them too).
- **Pack builder: stories over a Loop, sweep sheets, LoRA inputs and model families.** The planner reads from your description how the pack runs: **Story over a Loop** gives each frame the next story beat from `$iteration` with the character and outfit held, and **Sweep sheet** makes a few short wildcards to sweep with everything else held. **Runs as** under the plan's title shows it and lets you change it (and the number of frames). A subject you give it or any LoRA you name (character, outfit, style…) becomes an input you wire from an Injector, and a LoRA that stands in for a random pick replaces it only when you wire one in; the planner asks when it can't tell. A new setting, **Model: Per model family**, picks quality and negative tags per model (Pony score tags, Illustrious / NoobAI tags) from WP Model Info. The plan review adds what a story, a LoRA input or the model setting needs with one click, the test plays every story frame, and the install notes say where the Loop and Model Info go.
- **The chat can read a search result and look tags up on Danbooru.** When a snippet isn't enough, the chat can ask to read one page its own search returned: **Settings › AI assistant › Read result pages** fetches it from ComfyUI and keeps its text (never an address on your network), or uses your Crawl4AI or Firecrawl server for pages that need a browser. **Danbooru tag lookup** (off by default) gets a tag's wiki, aliases, implications and related tags, never posts or images. Each asks you first; **Don't ask before web calls** turns those cards off if you'd rather, and a short note you can dismiss says what leaves your machine.
- **Draft with AI makes tag groups and accepts groups.** In the wildcard editor's AI panel, "outfits tagged by style and the shoes they go with" now puts the style tags in a group and makes an accepts group (SHOES: loafers, sneakers, boots), tagging each outfit with the shoes that suit it. It used to write the shoes into the outfit text. The groups are listed under the draft and created with the options you tick.
- **The Pack builder knows how your model reads a prompt, and keeps adult packs to adults.** Name the model in your request (Pony, Illustrious, NoobAI, Animagine, Anima, Flux, SD 3.5, Qwen-Image, Z-Image, Wan, SDXL, SD 1.5…) and every item is written for it: the quality header, the order of the parts, its negative, or none for models that ignore negatives. The planner also follows a recommended pack structure: one wildcard per decision, details as filtered nested wildcards inside its options, constraints for what must agree, derivations for what follows, internal drivers for rules the image shouldn't name. A pack rated NSFW leaves out any option, value or rule that names a minor (child, teen, school uniform, an age under 18), and its template's negative always carries a youth block. Everywhere else (the chat, Draft with AI), an option that puts a minor in a sexual context is never kept.

### Fixes
- **Every random pick now rolls on its own.** Picks shared hidden random sequences, so changing one could move another: a derivation rule's `{a|b}` changed when an earlier rule fired, a fixed value changed when you added one above it, the colour in "@{Colors} jeans" changed when you added "@{Colors} jacket" before it, and every fixed values module (and every derivation) in a chain landed on the same position each run. Now each module use, and each pick inside it, has its own sequence, so adding, editing or firing one pick never moves another. **Saved and shared seeds give different prompts once after updating;** locked seeds still reproduce what you locked, Hold still holds, and negatives keep their own sequence.
- **No more "unknown field" warnings for Hide on fixed values and Hold on derivations.** The node offered both and the engine used them, but the instance check didn't know them. The assistant can now also set Hold on a derivation.

- **The chat keeps what it was writing when it starts using a tool.** An answer that streamed in and then turned into a search used to vanish; the text now stays above the steps.
- **Fewer empty answers from local thinking models.** When a model like Qwen3.6 writes its tool call inside its thinking and stops, the chat now finds the call and runs it, and an answer that still comes back empty is asked for once more with thinking off.
- **Copy and Try again sit on one row** under the last answer.
- **The chat no longer refuses to replace its own Test Runner run.** It said the Test Runner had unsaved changes when the only changes were from its previous run; it still asks before replacing a saved scenario or a run you edited. When two items share a name it now gets both ids back instead of "no item".
- **Constraints now apply to multi-picks from a nested wildcard.** `{2$$, $$@{Accessories}}` and `{1-3$$, …}` used to bring back options a constraint had shut out about half the time (a scarf in summer), because their weight of 0 was read as 1. Excluded options, and options you set to weight 0, now stay out.
- **The chat finds items by the ids it copies.** A chip written back as `[[id#Name]]` or `id#Name`, a `@{id}`, or a card number like "p4" now names the item. A multi-step ask ("make outfits that follow the season") used to create the wildcards and then fail to point the constraint at them.
- **AI-written rules and options use the engine's own syntax.** A tag filter written `!warm` (how other tools write NOT) is stored as `not warm`; it used to stop the whole wildcard. A multi-pick written `{2$$a|b|c}` gets its separator (`{2$$, $$a|b|c}`) instead of printing junk. A derivation that appends or prepends text gets a comma, so "tie" plus "watch" reads "tie, watch", not "tiewatch".
- **Empty variables no longer leave junk in the prompt.** The Assembler drops commas left at the start or end ("dawn, cloudy day,") and a joining word an empty variable left with nothing after it ("shadows with, gentle rain", "wearing with,"; only there, so a tag like "shirt tucked in" keeps its last word), and a doubled article ("wearing a a striped shirt") becomes one. A space before an emoticon tag (", :d", ", :3", "!?") is no longer removed.
- **Fix all in the Pack builder fixes all of them.** The findings go to the planner numbered, each with its item, and it is asked to add the constraints, derivations or items they call for. When AI review findings were among them, the AI review runs again on the new plan, so one that wasn't fixed comes back instead of disappearing.
- **Pack builder presets no longer copy other items.** A fixed values preset is told which variables the pack's wildcards and other items set and leaves them out (a preset that set $hair_style next to a Hair Style wildcard overwrote it), the plan review flags a preset planned that way, and the check reports two variables that always hold the same text. The preset is also told its own main variable, so "It doesn't set $style_tags" no longer comes back after two rebuilds.
- **The Pack builder's Build list follows run order.** Constraints used to be listed last, after everything else, which looked like they would run there; they now sit just before their target, in the order install keeps. A rebuild that didn't fix its problem now says **still:** instead of **fixed:**, and a constraint that never applied is reported on that constraint instead of as a general note.
- **The constraint assistant understands "only".** It was told an only rule keeps only the targets with an only rule, but the engine also keeps targets the same source side boosts or reduces (at their own odds), which is why previews showed chances for options outside the only row. It now knows that, and sees each tag group and whether it classifies or accepts.
- **The Pack builder no longer drops parts of a pack without saying so.** Tested on a real local model, plans that scored clean were missing what was asked: a "library" item that wasn't in your library was left out (the hair styles, the outfits, the style preset), an input could take the place of the wildcard a constraint needed (a season input erased the Season wildcard and all five season rules), and a pick the prompt never showed went unnoticed. Now a missing library item is made new, a constraint's wildcard is kept over an input, a constraint that still can't be kept is a plan finding (so **Fix all** sends it back) and a check note, and the template is told about any pick it doesn't show. Rules and combines read a pick that already rolled (`$race`) instead of rolling it again, so a title names the class you got, and in the tags style joined variables get commas between them. A constraint on an input (or on a wildcard named in words) gets its wildcard, a preset or combine without a variable gets one from its name, and negatives planned as a wildcard go to the template's standing negative. A rule testing a tag ("elf") or a piece of an option ("dense forest") tests the options that carry it, an option pointing at another of the pack's wildcards is sent back for a rebuild, `$x.tags`-style reads become `$x`, and the check flags inputs the prompt never reads and a variable the prompt shows twice (directly and through a combine). A library item that names your library itself ("User's Race Vocabulary") is left out instead of becoming an empty wildcard, a LoRA input the request never asked for is left out, and an input's example can't carry a `{a|b}` or `@{…}` pick into the prompt. A constraint planned as "never" whose rules only made the pair rarer now excludes it, and one planned as "only" without an only rule is rebuilt. Each wildcard is told the pack's other picks so it leaves their subject to them, the check flags two items that put the same words in the prompt and a pick only a constraint reads, and a rule that adds to a variable nothing set sets it instead (no stray leading comma). A "never" rule now excludes even when the model added boosts next to it, and an "only" built without any only or exclude rule is rebuilt. A "match $x" setting that none of a wildcard's options can meet is left out (it used to skip the match and its constraint on every run), a weight set on a tag (`weight long_hair=3`) weights every option carrying it, and an input the request doesn't say you'll give becomes a wildcard. The plan review flags one subject split into a wildcard per case (a spring, summer and winter top) and a template that joins picks with "or", and the check flags a rule that adds words its variable already holds. A subject split into a wildcard per case (winter, summer and mild tops and shoes) is merged into one wildcard per subject tagged by case, with a constraint from the season that keeps each case's options to it, so the prompt no longer lists every season's clothes. An "only" with excludes for some sources (no snow in deserts) now shuts the target out of every source it didn't allow, a near-zero "make rarer" counts as "never", and the check flags a pick that only rules read, which the image would never show. A constraint rule on a tag the target doesn't carry ("#snow" on a weather list tagged cold_ok / clear) now lands on the options whose text says it instead of being left out, and an "only" written as option pairs closes off the other sources too. Several "weight" settings on one use add up instead of the last one winning, a template that reads a combine and the variables it joins drops the separate reads, per-case rules left over from a merged split become one rule, and the plan review no longer asks for `$negatives`. A split named the other way round (`$animal_desert`, `$animal_forest`) merges too, and a "Select Animal" rule that picked among the parts goes with it; options tagged by a pick's cases (tops tagged winter and summer) now follow that pick, a request for "a weapon that fits the class" gets its rule, a rule naming several tags at once keeps the ones that exist, `weight solid=3, others=1` weights the rest, and only inputs the request names stay inputs. The plan review flags two wildcards for one thing (a base and a variation hair colour), and the check flags a wildcard whose options already name another pick (an outfit with its own shoes next to a shoes wildcard). A request that says "no sandals in winter" or "elves never use guns" now makes that rule exclude even when the plan wrote it as "reduce the odds", options the anchor rules only by name (fewer shorts in winter) get tagged with the seasons they fit and kept to them, each case-tagged wildcard follows one pick instead of a rule from every pick tagged the same way, a rule that rolls a wildcard a second time (`@{Outerwear:heavy}` written into `$outerwear`) is sent back, and long joined rules are cut between clauses instead of mid-tag. A rule's planned "#winter gets only #winter" now always lands as an only rule even when the model wrote something else for that season, a merged split keeps its seasons inside a "no shorts in winter" rule too, and a pick follows another only when its description says so (hair colours no longer have to match the eye colour, and a weapon list is never shut out by race rows it has no tags for). A template written as a sentence keeps its words when it also reads a combine, and a combine that makes its own pick instead of reading the variable it joins, or reads what the template prints itself, is sent back. A constraint planned with empty sides but "Source: $biome, Target: $weather" in its words keeps them instead of being left out, tags spelled with their role (`#summer_top`, `#winter_shoe`) next to a season pick become the seasons, rule tags match their singular or plural (`#sandal` for options tagged sandals) and their role word (`#mage_weapons` for `#mage`), a "never" in the request also reaches a rule written as "rarely" or named a Restriction, and a combine that writes out every option of a wildcard it reads is sent back. A split named by demonym (Elven, Dwarven and Human Traits next to a race tagged elf, dwarf, human) merges too, a rule the request says "fits" keeps only the fitting options instead of just boosting them, and a library "Vocabulary (Colors)" that no other item covers becomes a Colors wildcard instead of being left out. A rule that writes a wildcard's own pick with a new `@{…}` pick (a parka forced on summer) or adds more of the same kind to it (sandals added to the footwear) has that write taken out, since the wildcard picks and a constraint narrows it; a `{a|b}` of single letters in a combine is removed and other inline picks there are sent back; of two rules running each way between the same picks only the first planned stays, since the second never applied; and a template stops reading a variable twice or next to a combine that already holds it ("$weather conditions" included). A request like "snow only in cold biomes" now gets a rule that excludes snow for every other biome, whatever the model wrote; the planner's own conditions ("If $coat is present:") no longer print as a sentence in every prompt, a phrase that lost its word ("wielding a,") reads the pick it was missing, and the check flags a tag or variable name printed as text (`summer_outer`). The snow rule also asks for snowy options (hail and sleet count as snow) so cold places still get some, a value written as bare alternatives ("morning light|golden hour") becomes one pick instead of printing the "|", a constraint named in plain words ("Biome to Climate") keeps its sides, a library item made new next to the pack's own wildcard for it (Races next to Race) is left out, a rule the prompt never shows is sent to the template to read, and a template that reads a combine and a combine inside it shows it once. A cold place keeps its snow when its own row keeps only cold options, "an outfit and a weapon that fit the class" gets a rule for both, an option that means nothing ("no color variation") is left out, and a combine that joins what another combine in the prompt already joins is sent back. A library item made new next to the pack's own wildcard for it under another name ("Race Wildcard" next to Race) is left out, a rule the request asks for ("an outfit that fits the class") replaces an automatic keep rule on the same pick so something always fits, and the template starts with the pick the others follow when it never showed it (the season). A rule planned the wrong way round is turned around when the request says which pick decides the other ("the animal decides which habitats are possible"), so the habitat follows the animal instead of the second rule being dropped. Labels in a combine or template ("Footwear:", "Layering note:") and doubled words ("wearing wearing") are taken out, and a wildcard option that lists the other options ("staff, wand, sword, axe") is left out. Reads of per-season parts that were merged into one pick ($outfit_autumn) read the merged pick, a word the options already end on is not added again ("white hair hair"), the check flags an item that lists most of a wildcard's options at once, and when the request says the animal decides the habitat, the species (not its class) leads and is tagged by habitat. The other picks the planner adds to such a pack (an action, a detail) follow the habitat too, a rule keyed on tags neither pick lists gives those tags to the side it names, snow written in other words ("blizzard winds") follows the snow rule or is left out of lists the rule doesn't reach, option text written as tag ids (`polar_bear`) gets spaces in natural-phrase packs (tags-style packs keep booru underscores, and the check no longer flags an option that is its own booru tag), a subject the request never asked for (a detective in a weather pack) is left out, and a combine of phrases side by side gets commas between them. A template that reads a combine and a smaller combine it already holds reads it once (no more race and class printed twice), a group wildcard rolled apart from the pick it groups (an animal class next to the species: "insect, dolphin") is left out, a "snow only in cold" rule on a biome list without a #cold tag keeps snow to its arctic, tundra and alpine kinds, and lighting follows the weather when nothing else keeps it (no bright sun in the rain). A library item the request doesn't ask for is no longer pulled in to steer the pack (the library's Character Class driving an outfit pack's rules).
- **Local models can no longer write forever.** JSON requests to LM Studio, llama.cpp, OpenRouter and other OpenAI-compatible servers now carry the same output cap as Claude and Ollama. A model stuck in a loop used to keep writing until the 5-minute timeout (three times in a row in one pack); now its answer is cut off and retried, and a cut-off rule answer keeps the rules it finished (written once each) instead of failing.
- **New chat starts with an empty box.** Text left in the chat's message box (for example from a starter question or **Ask the assistant** on a docs page) stayed there after **New chat**.
- **The pack anchor warning and the plan review now agree.** A plan whose anchor was a run-time variable (`$model_family`, `$iteration`), one your canvas sets, or one a bundle you extend sets got a warning ("The anchor $setting isn't set by the pack") while the review said nothing, and the anchor was dropped. Those now count as set; an anchor nothing sets is a review finding with **Use $x** (when the pack sets something close) or **Clear it**. Plan notes get **Explain**, and a built item's problems get **Fix with AI**, **Explain** and **Dismiss**.
- **The derivation "any / is empty / has value" switch no longer sits on the value box,** and it is hidden under NOT exists, where there is nothing to narrow. Turning NOT on now always stores "does not exist". Existing derivations are unchanged: NOT only changed how a test is shown, never what is stored, and a test stored as "is not empty" (which used to show as "does not exist") now shows correctly as exists + has value.
- **Tags use the accent colour.** Active tag filters and the Tags page showed tags in green; they now use the accent colour like the tag filter list.
- **The AI pointer's caption no longer covers its own number.** The AI icon sat on top of "1." in the captions the assistant shows when it points at something.
- **Sweep combinations can clear a wildcard's options in one click.** Next to **all** and **enabled only** there is now **none**, so you can untick everything and pick just the few options you want instead of unticking them one by one. A wildcard with nothing ticked sweeps nothing until you tick one.
- **Editing a loop frame goes back to base when that frame goes away.** With frame #5 picked under **edit frame**, lowering the count below 5 or changing the sweep left you editing a frame that no longer existed (or now meant a different combination). It now switches back to **base**.
- **Frame locks and bypasses no longer come back on the wrong frame.** Lowering a Context Loop's count used to keep the seed locks and bypasses of the frames past it, and raising the count again brought them back. Now they are dropped. Changing a sweep moves each lock and bypass with its combination, or drops it when that combination no longer runs.
- **The loop's count is locked while a sweep is on.** The sweep decides how many frames run, so the count field now greys out and shows the sweep's frame count instead of looking editable.
- **The chat fits a model loaded with 16k of context.** Its instructions plus all 37 tool descriptions came to about 17k tokens, so with LM Studio or llama.cpp at 16k the first question failed with "exceeds the available context size". A new chat now reads how much context the model was loaded with and, when the full set wouldn't leave room to answer, starts with fewer tools (the rest stay one call away) and a shorter library summary; the history and tool results it re-sends shrink to what the window leaves. If the server still refuses the first request as too long, the chat tries again leaner, and when even that doesn't fit it says how much context to load the model with instead of showing the server's error.
- **Thinking: Off now works with LM Studio.** LM Studio ignored the switch the assistant sent, so thinking models like Qwen3.6 kept reasoning before every answer even with **Settings › AI assistant › Thinking** set to Off. The assistant now sends LM Studio's own off switch, the same one as the thinking toggle in LM Studio's chat, and the model answers straight away.
- **Ask to fix only shows where the assistant can fix something.** Notes that only inform (what a card kept, which card to apply first, a card that replaces an earlier one) now show in grey without the button.
- **Thinking: Off also applies to Draft with AI and the Pack builder** on LM Studio, llama.cpp and OpenRouter, so a thinking model no longer reasons for minutes before each plan or draft.
- **Multi-pick wildcards never pick a disabled or shut-out option.** A `2-3` pick used to fill its count with options weighted 0 or excluded by a constraint once the live ones ran out (an "only broom" rule still gave "broom, gun"). It now picks only live options, so it can come back shorter, and with none left it uses the fallback if there is one.
- **A derivation rule can use what an earlier rule in the same derivation wrote.** A second rule whose condition saw `$setting` from the first rule still printed it empty in its own value ("lamp light in "); its value now reads the earlier write too, like the actions of one branch always did.
- **An empty multi-pick no longer leaves a joining word behind.** A `0-2` pick that drew nothing printed "a knight with" from "a knight with $props", while an empty single pick printed "a knight"; both now print "a knight".
- **"Match variable" respects the option toggles and tag filter.** A wildcard set to match `$model_variant` could still pick an option you had unticked or filtered out, and used its fallback even with the fallback unticked. It now matches only the options that use can pick, and uses the fallback only when it is ticked.
- **A bundle inserted twice keeps each copy's constraints to itself.** With the same bundle added twice, the first copy's constraint also re-weighted the second copy's wildcard, so with "only" rules the second copy often came out empty. Each copy's constraint now applies only to its own copy (a constraint aimed at a wildcard in a different bundle still reaches it).
- **A held wildcard stays put when a constraint follows `$iteration`.** In a Context Loop, a wildcard set to **Hold across run** whose constraint source matched `$iteration` (a pose per frame, say) changed on every frame, because later frames re-resolved it with their own pose. It is now resolved with the first frame's inputs, in this Context or a later one, and keeps the first frame's pick all run.
