This release adds an AI assistant that runs on a model you choose, gives every random pick its own seed sequence, and moves the Community tab into its own frame. Every change, in full, is on the wiki: [Changes in 2.21](https://github.com/DumiFlex/ComfyUI-Wildcard-Pipeline/wiki/Changes-in-2.21).

> [!WARNING]
> **A saved seed can give a different prompt once.** Each random pick now rolls on its own sequence (see Fixes). Locked seeds still reproduce what you locked and Hold still holds, but a seed you saved before updating may land on a different prompt the first time.

### AI assistant

The assistant is new and **off by default**. Turn it on in **Settings › AI assistant**. It works with Ollama, LM Studio, llama.cpp or any OpenAI-compatible server on your PC, or with the Claude or OpenAI API and your own key. Keys stay on ComfyUI's side and never go back to the browser. **Test connection** checks the model, its context size and whether it can use tools. Local models need at least 16k of context, and 32k is recommended for chats that take several steps.

- **Draft with AI.** Every editor has an **AI** button. In the wildcard editor it writes new options in the style of yours, or rewrites, retags, re-weights or removes the ones you select. You tick through a list before anything changes. Fixed values, combines, templates, derivations and constraints get drafts too. With Thinking on Auto a local model answers the panels without thinking, so a 3-option draft takes seconds instead of minutes; a model that thinks anyway is stopped after about 4,000 thinking tokens and asked again, and the working line counts its thinking. Asking for 3 options lands 3 after duplicates are dropped. The rule and text panels see the variables your request is about in full and the rest by name only, about 4,000 fewer tokens on a large library. A name two wildcards share (two Outfit wildcards) is no longer guessed: the panel points at the one you mean by its variable. When new options of a one-thing wildcard (Hair style) also set something else you didn't ask for (an outfit), the panel asks once more without it. A text panel that loops on the same words is stopped after about 1,500 tokens and asked once more, so a stuck template answer comes back in seconds instead of four minutes, and a Fixed values, combine or template draft that leaves out a variable your request names ("$light is warm lamp light") is asked once more for it. Try again and Refine no longer share one "Answer n of m" pager: each request is a line above the answer with its own **try 2 of 3** switcher, different refines of one answer get a **refine 1 of 2** switcher, and refining any try branches from that try, so you can compare tries of the same request side by side. A number in the request now sets **How many** ("draft 6 desert weather options" drafts 6, not 10), also when the chat opens the panel. The model sees the tags each existing option has, and a new tag it puts on every new option, the wildcard's own library tags and negatives nobody asked for are left off and listed under the result. Retag that "adds" a tag keeps the options' other tags, "half as likely" halves each option's current weight instead of setting 0.5 (which made a 0.1 option five times more common), a weight that moves the other way than asked is left out, and a rewrite or retag of "every" option that skips some is asked once more for those.
- **Draft panels drawn for each item.** The Fixed values panel shows one row per value (variable, value, negative), marked New or Changed with the old text struck through, and only the rows you tick change. The Combine and Template panels show the text and its negative apart, each with its own tick box, the variables it reads (new ones dashed) and a few lines of what it prints with your own options. A Derivation request that changes a rule you have ("rogues should be called Shadowblade") now edits that rule, marked **Changes rule N**, and keeps its other branches and its ELSE, instead of adding a second rule. Held to the request in code: "6 more, bolder" drafts 6 and "one option each" is no longer a total of 1; extra options are cut evenly across the tags you asked for, and an answer that tags nothing when you asked for tags is asked again; Remove keeps an option whose own reason says it fits and asks again when it removes everything; a Danbooru rewrite names tags your tag list lacks; a fixed value that repeats another is left out and its negatives lose repeats and words the value prints; a combine that reads its own variable keeps the rest, and "with $hair_color hair" loses the second "hair"; templates turn `{name}` into `$name`, leave out loop and model variables you didn't name, start a Pony prompt with its score tags, drop quality tags for Flux, move "bad hands" to the negative and keep a "short" negative short; a derivation split into "when A", "when B", "otherwise" is one IF / ELSE IF / ELSE, "add 'x' to $y" adds, and one bad action no longer costs the rule.
- **Chat.** The **AI** button in the top bar opens a chat that can search your library, test stacks on the real engine and answer from these docs. Changes come back as cards you **Apply** or **Dismiss**, with **Undo**. Type **@** to name an item or **$** for a variable, or select any text in the manager to have it explained. Picked items show as chips while you type, and each reply shows how long it took. Adding a tag to options keeps the tags they had, and a card that takes a tag off every option warns when a constraint still has rules for it. Change cards draw the change the way the editor shows the item: a wildcard edit lists the options it touches with + for new ones, removed ones struck through and old → new for text, share of the draw, tags, negative and fallback, with the untouched ones folded into a count; a change to an item's description, tags, category or rating shows old → new with the category's own chip, and category, tag and bulk cards show library chips instead of lines of text. A derivation change shows its IF / ELIF / ELSE blocks with the changed branches marked (a dropped ELSE struck through), a constraint change marks the changed cells of its grid, and a bundle change lists its items in order with added, removed, moved, switched-off and new use settings marked. A fixed values change shows its table with the changed cells old → new, a template or combine change marks the words it adds and drops and the variables it starts or stops reading, and a delete card lists what goes (with category and rating) and what a dropped category or tag leaves behind. A test card that compares to before now gives an old value its real share instead of 0%, and the test step names the items it ran rather than their ids. In replies, a variable is drawn like the editors draw it (accessors in amber, `.neg` in red, and variables the run sets, like `$iteration` or `$model_family`, marked read-only), an item name the model put in backticks is a chip like any other, and a list of three or more items shows as an item list with each one's category chip. The reply is checked against its cards: a weight or factor no card sets, a bundle move the card doesn't make, or "created successfully" before Apply gets a note, notes about missing cards no longer appear under delete and tidy answers, and tool names are said in plain words. A delete card only names what you asked to delete ("delete the Hairstyle wildcard" with no Hairstyle no longer offers Hair colour, and "the Weather category" never deletes the Weather wildcard), and with deleting off the reply says where to turn it on. "Switch off" in a bundle switches the child off instead of removing it, bundles can move a child after or before another, a rewritten derivation rule keeps its ELSE, a typo fix adds the tag it meant, and a new item or rename that takes an existing name warns. A test right after a change card runs with the change and the items that set what it reads, and Explain on selected text only explains. The Only rule is now described as a guest list in the docs, the matrix legend and the chat.
- **Pack builder.** In the sidebar. Describe a pack and it plans the choices and rules, asks a few questions, builds every item, tests it on 200 seeds, fixes what failed and installs it as one bundle with one Undo. It knows how each image model reads a prompt (Pony, Illustrious, Flux and more) and can plan a story over a Context Loop. Its item builds skip a local model's thinking on Auto like the Draft with AI panels, the Negatives setting now holds for every pack (Template only or None leave options without negatives), and an outfit that accepts two kinds of shoes no longer gets an empty Shoes option that left some prompts barefoot. A rule on a shared list ("each shirt in a colour from one list, colours fit the season") now runs before the items that draw from the list, so the colour in the shirt follows it; the list no longer prints a second colour at the end of the prompt, and the test checks the colour in the shirt. Fixing stops sending a problem that came back unchanged after a rebuild. The plan now holds to your request: "a hat 30% of the time" leaves the hat out in 70% of runs, "the same hero in every image" holds the hero, and an outfits pack shows the outfit, set by the code itself. A rule the request names with no rule in the plan ("winter never gets pastel colours") goes back to the planner. A plan that runs into the model's output limit is asked for once more, shorter. A rule written as prompt text ("exclude pastels") is left out instead of printed, an outfit with rules on it no longer picks two (one casual and one formal left only boots), a shared list drawn by another wildcard no longer breaks its rule every run, and the test catches a $name the prompt prints as written. A rule on a colour drawn from a shared list now reaches the drawn colour, "sneakers with casual, heels with formal, boots with either" becomes the rules when the planner wrote them wrong or left them out, a story's beats no longer describe a different hero each frame, and one option that crams a dozen heroes together becomes a dozen options, and a request for "every image of a loop" runs as a story instead of single images, so its held hero stays held. A new Plan drafts choice, When needed (now the default), drafts the plan a second time only when the code sees a problem in the first and keeps the better one, so a clean first plan costs nothing extra. Each wildcard's options are now asked for grouped by the value its rules are about (winter, summer), so every value has options from the first try instead of a second call to fill the gaps. A template that starts with "$quality $style" no longer prints both twice, and a negative that names a $variable nothing sets no longer prints it as written. A colour wildcard whose options already name their colour no longer gets a second, different colour from a shared list in front, and a list of up to 10 values gets an option for every value. The Template, Combine and Fixed values panels can no longer run on to the output limit on one long line. A plan with "Casual Outfit" and "Formal Outfit" printed both in every prompt and its shoe rules left no shoe, so the fallback was always taken; the two are now one Outfit slot with a casual and a formal kind. A rule that adds to the pick it reads ("cap" after "a person in a baseball cap") is left out, the test now sees rules keyed on a rolled tag fire instead of reporting them as never fired, and a rule whose words read a variable ("wearing a $top") is checked against the top the run picked. "A person who wears a hat 30% of the time" now leaves the hat out, not the person, even when the planner wrote the share the wrong way round or gave the hat two picks. Two rules that add words to the same thing on the same value ("at night: moody shadows" and "at night: volumetric darkness") now both apply; only the first did. A pack for Pony and Flux no longer rolls the image model or the prompt style as a pick nothing reads, and no longer prints Pony's quality words (with "1girl, solo") on every Flux image: the checkpoint decides, a fixed value can no longer write over $model_family, score tags stay on the Pony row of the quality rule (and come out of style presets and other wildcards' options), the quality rule is one if/else even when the model writes it as two (the second's "otherwise" used to write over Pony's tags), and $quality stays in the template (the duplicate check used to take it out, since the test runs load no model). An outfit wildcard named like its kinds no longer prints a bare "casual" or "formal", and a shoe a rule names ("sneakers with casual") becomes an option when the model's options still leave it out. A rule that adds words ("hammer" + "blade") now joins them with a comma instead of gluing them into one word, and the test reads the prompt text too: a rule that held on the picks while its banned words still showed up through another item is now broken with what the prompt showed, instead of "rules held, no warnings". A constraint with no rules and a rule that prints a second outfit next to the picked one are problems, the template no longer prints loop or model variables or skips a slot nothing reads, Pony rating tags stay off packs not just for Pony, the quality rule has rows only for the pack's model families, negatives drop the pack's own options and repeats, a library wildcard is reused only when it fits the slot, and "drop the hoods" keeps hoods out of that slot's options. A constraint or derivation the code wrote has **Change the plan** instead of a Fix with AI that would write it the same way, a problem still there after a fix says why, and an item or review cut off at the output limit is asked once more. After the build, **Fix all with AI** under the test run rebuilds every item with a problem at once, and Extend with AI no longer offers **Add to the bundle** when only the template built (the install was refused with "nothing is built yet").
- **Pack builder settings that fit the pack.** The Settings step lists the settings that fit your request, each with why: Natural phrases and no negatives for Flux, Tags for Pony, Per model family when the pack is for two models, NSFW for an explicit request, Reuse what fits when you ask for your own wildcards. **Use recommended** takes them; nothing changes until you press it. The chat's plan card recommends settings too, and its button is now **Open in Pack builder**: it fills in the description without starting the plan, so you can add reference images and check the settings first.
- **Small local models.** A 9B model on a 16 GB card is a supported setup. The assistant fits its instructions and tools to the model and works through bigger asks one step at a time. A message that touches a feature (refs, constraints, rules, negatives and more) brings a few lines on how it works. Tool calls can only name items that exist, and edits only the ones you pointed at. Each step offers about ten tools that fit the message, and a question gets an answer instead of a card. Before it finishes, the code checks its cards against what you asked for (constraints, "only" rules, fallbacks, negatives, tag filters) and asks once for what is missing, a reply that talks about something no card has says so, a reply that claims a change it never made gets one more step with only the change tools, and a tool it keeps repeating is closed for the rest of the answer.
- **Other languages.** Write to the assistant in any language the model knows. The checks that read your request (question or change, how many options, did the cards get the negatives, fallback or rules you asked for) used to understand only English, so a short German or Japanese ask lost the chat's change tools and a German draft lost the negatives it asked for. A message that isn't in English is now read into English by one short model call first, for those checks only; the model still reads your own words, and English messages cost nothing extra. **Settings › AI assistant › Chat › Language you write in** can set it to English or Another language.
- **Thinking per model.** The Thinking setting lists only what the chosen model takes: Off and On for a model with an on/off switch (Qwen under LM Studio), or its own levels for Claude, OpenAI, OpenRouter, Ollama and llama.cpp. A refused choice is remembered for the model, and if thinking uses up a whole reply the assistant asks again with it off.
- **Sampling.** Settings › AI assistant › Advanced takes optional top K, top P, min P and repeat and presence penalties for the model, sent with each request to a local or OpenAI-compatible server, so a model card's values work without changing them in LM Studio or Ollama.
- **Settings.** Settings mark the recommended choice for each option, and **Reset to recommended** puts them back without touching your provider, keys or models (a context window bigger than 16k is kept). A warning shows when ComfyUI is open to your network (`--listen`). **Type out replies** (off by default) shows the chat's reply word by word as the model writes it, and its Thinking box as it thinks, local models included; a reply that has sent nothing for ten seconds says the model may be busy. **Suggested models** for your own server name the model only (Qwen3.6 35B A3B, Qwen3.8 27B and Qwen3.5 9B, all tested, plus two untested writers with why they were picked); which build you download is up to you. **Short tool list** (Advanced, off by default) gives a small model one line per tool and each tool's full description the first time a step offers it, about 2,000 fewer tokens per step. **Debug log** (Advanced, off by default) records every AI request with the prompt as sent, the reply, thinking, tool calls and tokens; a **Debug** button in the top bar lists them with **Copy debug** for bug reports, and each one is also saved as a file.
- **Safety.** Web search, reading a result page and Danbooru tag lookups each ask first; **Allow for this chat** lasts 8 hours. No AI feature writes content that puts a minor in a sexual context, or sex without consent (rape, "against her will", unconscious), and a request for either is refused, in English and nine other languages. The guard reads negations ("adult women, no children, no minors" is no longer cut, "no older than 15" still is) and leaves adult body words (petite, small breasts, innocent look) alone. Items the chat makes are rated NSFW when tagged #nsfw or explicit, the chat and Organize no longer lower NSFW to Safe or take #nsfw off unless you ask, the chat's search filters by rating, a pack's "rating explicit" is written as `rating_explicit`, and a template draft asked for a negative "against anything youthful" gets the youth words.

### Editors and nodes

- **Image Filter: Grid, Detail and Zoom.** The picker has three modes behind one switch at the top (**G**, **D**, **Z**), in a window that keeps its size, with the pick count and Keep buttons always in the footer. **Grid** picks fast: click or **Space** on the image under the mouse, and tile sizes **S / M / L / Fit**. **Detail** shows one image next to its size, seed, values, prompt, negative and mask, with a **Pick** / **Picked** button (**P**), ‹ › beside the picture and a strip of every image; the prompt fields show only when a prompt or CLIP is wired. When painting a mask, a ring under the mouse shows the brush size. **Zoom** finally zooms: **Fit / 100% / 200%** and − / +, scroll to zoom toward the mouse, drag to move, double-click for 100%, **F** for fullscreen, and ←/→ keep the zoom and the spot on the next image, so you can check the hands in every frame. Zoomed in, a mini-map shows where you are (click or drag it to move), the bar fades while the mouse is still, fullscreen has a strip of the frame's images with **Keep picked**, the picture says when it is picked, and **C** shows two images side by side, locked to the same zoom and spot. The zoom is a new kit piece, `WpImageZoom`. Detail's side panel puts **Pick**, **Compare** and **Pick frame** at the top and the rest in three tabs, **Values**, **Prompt** and **Mask**: each value is marked in the prompt in its own colour (the same colour in Values), hovering a mark says which variable set it, the prompt and the negative have copy buttons, and a **text only** tag replaces the long no-CLIP note. A loop's images sit together in Detail's strip, one group per frame, and in Grid each frame says how many of its images are picked, with a **Pick frame** button.
- **Image Filter labels and mask preview.** A new **labels** output sends a label for every image, in step with **images**: `#3 · red · pencil · 2` by default (frame or loop number, the swept option names, the image number), or the name you give it under its tile in Grid or under its title in Detail. An item that holds several images has one line per image. The new output is last, so saved workflows keep their links. Once a mask is painted, the **Mask** tab previews it **Over image** (tinted) or as **Mask only**, white on black as the **masks** output sends it.
- **Image Filter mask tools.** The mask painter has **Lasso** (drag around an area to fill it) and **Fill** (click inside an outline you painted) next to the brush, **Paint / Erase** for every tool (**X** swaps), **Hardness** for soft edges that blend in without a seam, **Strength** to mask part-way, **[ ]** for the size, and **Undo / Redo** (Ctrl+Z, Ctrl+Shift+Z).
- **Variables are coloured text** in combine, derivation, negative and template text, instead of chips.
- **Negatives can change per use.** On the node and in bundles, a fixed value's or combine's negative can be changed for one use and reset to the library's.
- **Constraint preview.** The constraint editor shows each target option's chance for every source option before you run anything.
- **Docs rewritten in plain words.** Every docs page and node help panel is shorter, with new screenshots of the current nodes. New **How to** pages cover variations in one click, making two picks agree, keeping something the same, sharing a pack and fixing common problems. The AI docs are split into short pages, and importing A1111/Forge wildcard packs has its own page.
- **New guides** for pack structure, writing prompts per image model, and adult (NSFW) packs.
- **A new loading mark** replaces the spinners in the manager.
- **One accent colour.** The manager now uses the logo's indigo as its accent (it was violet), the same one the canvas nodes use. Buttons are flat instead of gradients, and the dashboard and What's new headers are plain cards. A violet you picked yourself in **Settings › Appearance › Accent color** stays.
- **Colour themes and looks.** **Settings › Appearance** (and the Tweaks panel) has two new choices you can mix. **Colours**: Orbit, Native (ComfyUI's own greys), Nebula, Tide, Ember and High contrast, each in dark and light. **Look**: Orbit, Crisp, Soft, Terminal, Editorial, Compact and TUI, which change corners, type, borders and how a selected item is drawn. **Accent color** now starts on **Theme's own**; an accent you picked yourself stays, and High contrast keeps its own so text stays readable. Module kind colours stay the same in every theme, and the canvas keeps ComfyUI's colours. See **Docs › Overview › Themes and looks**. Every screen follows the look: corners are square in Terminal and TUI and near-square in Crisp everywhere, not just on buttons and cards; the Settings list, Test Runner list, Pack builder steps and Dashboard tabs show the selected item the look's way; TUI checkboxes read `[x]` without the tick beside them, also the **Favorites only** filter; and the **Theme's own** swatch is a clean half-and-half circle.
- **Component kit.** **Settings › Advanced › Component kit** (or **Docs › Reference › Component kit**) shows every shared control (buttons, fields, dropdowns, checkboxes, chips, dialogs, prompt boxes, the selection bar, colours and type) with when to use each, for anyone building on the extension. It also has new shared pieces for building screens: a popover, a dropdown menu, styled tooltips that also show from the keyboard, and a side drawer. Right-click menus now stay on screen near the window edges and close when the page scrolls, dropdown menus follow their button as the page scrolls, and dialogs on the manager pages wear the manager's colours. Menus, dropdown lists and popovers have a smaller, tighter shadow that fits their size, and dialogs a softer one. Seven more pieces join it: tabs and a segmented control that you move through with the arrow keys, a folding section, a banner in six tones, a copy button that turns into a check when the copy works (also over plain http), one close button, and a data table with sortable columns, row ticks and loading rows. The manager now uses them: Import / Export, the test runner and the bundle picker have the new tabs; the settings, the AI panels, the import conflict dialog and the condition switch have the segmented control; dialogs, drawers and panels share one close button that also shows Esc; ids in the library lists copy with a click or the keyboard; the draft, restart and load-error banners are one Banner; and the Tags and Categories pages can be sorted by any column. Seventeen more pieces are in the kit for the screens to move onto: a progress bar, loading shapes, a count or status badge, a steps header, page numbers and Load more, a slider, a tag box, rename in place, a file drop area, a list you reorder by dragging or from the keyboard, panel resize handles and a split view, label and value rows, a code block with copy and wrap, shortcut keys that show ⌘ on a Mac and Ctrl elsewhere, a divider and a toolbar you move through with the arrow keys. Eleven more join them: a dropdown you can type in to filter (one pick or several as chips), a date picker you can drive from the keyboard, a two-handle range slider, radio choices with a line of help each, avatars with initials when there is no picture, a timeline of events, a word or line diff that also says "removed" and "added" to screen readers, an image grid that opens a full-screen viewer you step through with the arrow keys (with Fit, 100% and 200% zoom where a screen wants it), a list that stays smooth with thousands of rows, and text only screen readers hear.
- **Controls tidied.** Buttons, fields, dropdowns and number fields share one height scale (24, 32 and 40 px), so a button and the field beside it line up, and a button's label sits level with its icon. Every hand-made shadow uses the shared shadow sizes. A disabled checkbox or radio turns grey, a disabled button fades and a saving button keeps its colours with a small sparkle; a read-only field is dashed with a lock. A chip's ✕ is a plain mark that no longer makes the chip taller, and a dropdown's clear ✕ sits apart from its arrow and shows on hover. Card titles read as titles, an empty list no longer fills most of a small card, the colour picker shows its hex and the icon picker names its icon. Dropdowns, the colour and icon pickers and the hover card on a `@{}` ref follow their field when you scroll. Pages and panels that load show the full logo; tight spots show the sparkle.
- **One of each control.** Every search box (node pickers, lists, settings, docs, the sidebar, import and export) is now the same box: a magnifier, a ✕ to clear it and, on long lists, a "3 of 12" count inside it; Escape clears it before it closes anything. Every number field, in nodes and in the manager, has the same up and down arrows. Category pills, toasts and the manager's "Are you sure?" dialogs each look the same everywhere: the manager's confirm dialogs are now real manager dialogs, so Tab stays inside them and focus goes back to the button that opened them.
- **One switch, one set of tabs, one button, canvas and manager alike.** The canvas on/off switches (Hide from prompt, Hold across run, Lock pick, the derivation rule switches, seed rows, Seed List, Context Loop and sweep), the Debug viewer and module picker tabs, and the joined-button pickers (Cleaner mode and intensity, Image Filter mode, picker layout and paint tool, constraint reach, loop strategy) now use the same controls as the manager, and every button in the canvas dialogs (the editors' Save / Cancel / Reset overrides, the pickers, confirm, Image Filter, Debug viewer and seed rows) is the manager's button at the canvas size. The on/off box on module, bundle and injector rows is the shared checkbox, with a focus ring and a tick, and the Settings live preview shows the same pieces. Arrow keys move inside tabs and pickers, Space and Enter flip a switch, and their hints show from the keyboard. The manager's off switch is no longer almost invisible in light mode.
- **The last hand-made node buttons are gone.** The small lock, internal and remove buttons on module, bundle, injector and Model Info rows, the Context toolbar's collapse, expand and show-all buttons and the row fold arrows are one shared row button, with a focus ring and hints that show from the keyboard. Every node dialog closes with the same ✕ (it shows Esc). The editors' reset buttons, Push to library, the template and module pickers (their favourites, hide-added and filter toggles light up when on), Retry, Reattach, the Assembler's template buttons and the Loop and Seed List seed and sweep buttons are the shared button too, and the "Add rule", "Add template row", "Add extra exception" and "Add new $var" buttons are one dashed add button. At the template-row limit the Injector's add button now says "Template rows full (5 max)" instead of only greying out. The Debug node's rule cards and the constraint matrix legend fold like every other folding section, the Debug seed and module id chips and the editors' id chip copy with the shared copy button (a tick says it worked), the Cleaner's blocklist mode is a segmented choice and its Blocklist button the shared button, a frame's "Revert to base" is the shared button, and the Sweep panel's move and remove buttons and the tag pool's fold and Advanced buttons match the rows.
- **The rule grid's cell editor is the shared popover.** On a node and in the library, clicking a constraint matrix cell opens its rule in the same floating panel every picker uses: it stays on screen, follows the cell when you scroll, closes on Escape or a click outside and gives focus back to the cell, and its Neutral / Exclude / Boost / Reduce / Only buttons are the shared button. The exceptions' mode chip says which mode a click moves to, the Context toolbar's "Refresh N drifted" is the shared button, derivation rule cards fold like every other folding section (their on/off switch now sits at the right, beside the drag grip, so flipping a rule never folds it), the import and export pickers' sections fold the same way with their select-all box in front, and the Cleaner's rules are tick boxes like the node rows' (the label still toggles).
- **The Test Runner's tables sort.** Samples and the inspector's option list are the shared data table: click Seed, a variable, Warnings, Weight or Picked to sort by it, and the open seed stays highlighted. Rows still open their trace on click or Enter.
- **The manager's own choice buttons use the shared pieces.** Tweaks › Density and the Test Runner's Range / Random are segmented choices you can move through with the arrow keys, the AI provider list in Settings is a radio group (one Tab stop, the arrows pick a provider; each still says Local or Cloud and shows a key once one is saved), and the import conflict actions (Skip, Import as new, Import anyway, Link to existing, Include deps) are one joined button group you Tab into once.
- **Docs search finds words, not just titles.** The search box on the docs page now searches the text of every page (and the Settings), lists each matching section with the words marked, and opens a result at that section; **/** jumps to the box and **Enter** opens the first result. Long pages show an **On this page** list beside them on a wide window, every section title has a link you can copy, and each page ends with **Previous** and **Next**.
- **The docs page uses the kit too.** Click a screenshot and it opens full screen with Fit, 100% and 200% zoom, and ← / → step through the page's other screenshots. Tips and warnings are the shared banner, "How it works" boxes fold like every other folding section, shortcuts show as keys (⌘ on a Mac, Ctrl elsewhere), the Modelfile and the pack templates in the guides are code blocks with a copy button, and the warning list marks each one with the same coloured dot as the nodes.
- **Shortcuts look the same everywhere.** The editor windows on the node, the pickers, the seed list, the command palette, the shortcut sheet and the search boxes draw their keys with the shared key caps (⌘ on a Mac, Ctrl elsewhere), and the shortcut sheet says "↑ or ↓". Error details, database reports, the Test Runner template, saved Context data and the Push to library / Save template previews are code blocks with copy and wrap buttons.
- **Tweaks, Version history and Database use the kit.** The Tweaks panel is the shared side drawer: Escape closes it and focus goes back to the button that opened it. Version history is a regular dialog (Tab stays inside it) and the saved snapshot is a code block you can copy. The Database card's file and schema details line up as one list, with a copy button on the path. The top bar and the Dashboard draw the logo inline instead of loading the icon file.
- **Autocomplete can write tags the way the model reads them.** Two new settings, in ComfyUI's panel, the Display playground and **Settings › Autocomplete** (Manager and Canvas): **Write tags with spaces** puts `blue_hair` in as `blue hair` (short emoticon tags like `^_^` keep theirs), and **Escape brackets in tags** puts `fate_(series)` in as `fate_\(series\)`, so the brackets are not read as a weight. Both are off by default.
- **Row buttons on hover.** A new **Row buttons** setting (ComfyUI's panel, the Display playground, **Settings › Canvas**) shows the lock, internal and remove buttons on WP Context rows and bundle headers only when the pointer is on the row. A pressed lock or internal button always shows, since it tells you something.
- **The Display playground previews behavior too.** Under the module preview, **Show sample toasts** pops an info, a warning and an error so you can see Toast lifetime and Suppress info toasts at work, a small prompt box shows autocomplete with the max suggestions, minimum characters, `, `, spaces and bracket settings applied to a few sample tags, and a short conflict list shows what Validation strictness lets through.

### Wildcard pack import

- **Pack logic carries over.** Dynamic Prompts and PPP variables, template arguments like `__outfit(season=winter)__` and PPP `if` blocks used to be dropped or left as text. They now become stacks: bundles that roll each variable once, keep picks consistent with constraints and write the prompt with a Combine.
- **Model checks.** A PPP test on the model, like `_is_sdxl` or `_is_pony`, becomes a stack that reads **WP Model Info**.
- **Negatives and LoRAs.** PPP `<ppp:stn>` and Umi `**text**` go to the option's negative, and PPP LoRA commands become `<lora:…>` text.
- **Umi AI packs.** Umi YAML entries keep their tags, and tag queries like `<[female][casual]>` pick from the matching entries.
- **Tables.** Subfolders that repeat the same list names become one wildcard per list name, tagged by folder. Tag groups can be renamed in the review.
- **Template copies fold.** Entry points that are copies of one template, differing by one value, become one wildcard steered by a choice.
- **Sample rolls.** The review shows a few prompts each stack and entry point makes, rolled on the real engine.
- **Installed folders.** The wildcard folders of Impact Pack, Dynamic Prompts, Easy-Use, PPP and LoRA Manager are listed for a one-click convert.
- **Bundles are stacks only by default.** The old bundle per folder is still under **Bundles** in the settings.
- **Same look as the rest of the manager.** The Wildcard packs tab and the Import tab now use the manager's own checkboxes, dropdowns, fields, search box and buttons instead of the browser's, in light and dark. The role cards and "How it carries over" no longer wrap onto a second row when a pack has stacks.

### Community

- **The Community tab runs in its own frame**, so nothing it loads can reach ComfyUI or other custom nodes. Your community sign-in moves over on its own.
- **Broken packs are refused before install.** Import, Community install and dependency downloads check every item and name the one that's wrong.

### Fixes

- **Search (Ctrl K) is grouped.** With nothing typed it lists **Recent** first (what you ran from it and what you opened lately), then short groups: Go to, Create, Actions, Library and Categories. Typing still gives one ranked list, and the arrow keys keep the row they land on in view.
- **Row checkboxes are easy to see.** The empty box you tick to select rows on Wildcards, Fixed values and the other lists has a visible edge (it was a dark square on a dark row) and lights up on hover.
- **Accent colours have names.** Tweaks and **Settings › Appearance** name each accent under its swatch (Theme's own, Indigo, Violet, Teal, Rose, Amber, Custom), and Custom shows a colour wheel until you pick one instead of an icon.
- **The assistant's header fits every drawer width.** On a narrow drawer the title and buttons share the top row and the model and thinking pickers share the second, instead of wrapping wherever they ran out of room.

- **Bulk bar stays in its box.** With many items selected, the list pages' bulk bar wraps its buttons onto a second row when they don't fit (Delete used to stick out past the edge) and keeps "39 selected" on one line.
- **The same controls everywhere.** The AI panels, Pack builder, test runner and canvas widgets (Loop sweep, Image Filter, seed rows, Display playground, template and module pickers) use the extension's own checkboxes, dropdowns, number arrows and buttons instead of the browser's, in light and dark.
- **The Display playground works from Settings again.** Opened from **Settings › Wildcard Pipeline**, it could not be clicked, because ComfyUI's Settings dialog turns off clicks outside itself. Its controls now respond, Tab stays inside it, and Escape or a click beside it closes only the playground, leaving Settings open.
- **The autocomplete switches look like ComfyUI's.** The Booru tag, LoRA and Embedding autocomplete switches in **Settings › Runtime behavior** are now drawn the same as ComfyUI's own switches (size, colours, light and dark), and still show their "286,337 tags installed" or "50 LoRAs found" count beside them.
- **Canvas settings stay in step with the manager both ways.** A change in ComfyUI's settings panel or the Display playground now shows at once on an open **Settings › Canvas** page in the manager (it used to wait until you clicked back into the tab). **Settings › Autocomplete** shows each setting twice, **Manager** and **Canvas**, so you can see and change the canvas copies (the same values as ComfyUI's panel) without leaving the manager; they can still differ on purpose.
- **The playground's bundle has its frame on an empty canvas.** With no WP Context node on the canvas yet, the Display playground's preview bundle lost its frame and child indent; it now looks the same as on a real node.
- **Subgraph badges follow Validation strictness.** With **Relaxed** a subgraph badge no longer shows info notes, and with **Permissive (off)** it no longer shows at all, the same as the rows inside.
- **AI settings follow the provider and model.** Thinking, Model size, context, Tool format, Sampling and the small-model options are kept for each model, so Medium thinking set for Claude no longer sticks on a local Qwen that only takes on or off.
- **The AI working line no longer cuts its words short.** "Writing · 38 tokens…" or "Writing prompts…" could lose its last letters ("Writing · 38 token") while the line changed width, or for good, and a longer word showed as "Rolling the d…" until the line had widened. The line now widens at once for a longer word and narrows only after the old word has faded, and a token count ticking up no longer fades in and out.
- **Library pages update when something is deleted.** A deleted category stayed on the Categories page until you refreshed. Undo now brings rows back on screen, chat changes refresh every library list, and Recently opened drops deleted items.
- **Every random pick rolls on its own.** Picks used to share random sequences, so changing one could move another. This is the change behind the seed warning above.
- **Constraints hold on multi-picks.** `{2$$…}` picks and `2-3` picks no longer bring back options a constraint or a weight of 0 shut out.
- **Clear template clears the negative too** on the Assembler.
- **Cleaner prompts when a variable is empty.** The Assembler drops leftover commas, dangling joining words and doubled articles.
- **`!warm` and `{2$$a|b|c}` work** the way other tools write them.
- **Rules and runs.** A linked-picks rule no longer empties a wildcard that links onward, a bundle inserted twice keeps each copy's constraints to itself, a held wildcard stays put over a Loop, and a later derivation rule reads what an earlier one wrote.
- **Clearer warnings.** A deleted pinned option says **Pinned option missing**, recipe wildcards no longer warn on every run, and Hide/Hold no longer show "unknown field".
- **A quieter ComfyUI console.** With meaning search on and the embedding server stopped (LM Studio closed, say), the console printed "embedding the library stopped" every few seconds while AI settings were open. It now prints once, waits 30 seconds before trying again and longer after each failure (up to 10 minutes), says once when it works again, and **Settings › AI assistant › Library index** shows why it paused. A wildcard that fails on every run, a broken preview and a broken tag file also print their error once instead of on every queue or keystroke.
- **Long sessions stay fast.** Deleting a node shuts its widget down, and WP Context no longer leaves a database connection open on every run.
- **Smaller canvas download.** The canvas colour sheet loads once instead of being copied into 15 separate files, about 38 KB less (gzipped) to load across the nodes.
