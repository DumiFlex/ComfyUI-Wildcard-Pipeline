### Features

- **Draft wildcard options with AI, using a model you choose.** A new **Settings → AI assistant** page (off by default) connects the manager to Ollama, LM Studio, llama.cpp or any OpenAI-compatible server on your PC, or to the Claude or OpenAI API with your own key. Pick the model from the server's list, press **Test connection**, and set how long a local model stays loaded so it hands the GPU back to ComfyUI. Then the **AI** button in the wildcard editor writes the number of options you ask for in the style of the ones already there, reusing your tags. You see the list first, untick what you don't want, and **Add** puts the rest in the editor like pasted options; nothing is saved until you press Save. Options can use `{a|b}` picks and point at other wildcards by name (`@{Colors:warm}`); the assistant turns the name into a real reference and checks the tag filter against that wildcard's tags. Duplicates, options that read a `$variable`, and references to a wildcard or tag you don't have (or back to the wildcard itself) are left out and listed. The same panel's other tabs edit what is already there: **Remove** finds options matching what you describe, **Rewrite** changes their wording, **Retag** sets their tags and **Weights** makes them rarer or more common, on every option or just the selected ones. Each shows a before/after list to tick through before anything changes. The fixed values, combine and template editors have an **AI** button too: it writes a style preset with its negatives, a combine that joins your variables, or the Assembler prompt with a standing negative and `$negatives`, and warns about any variable nothing sets (a template never gets `{a|b}`, which the seedless Assembler would print as is). The derivation and constraint editors have one as well: describe the rules ("when $class is mage, set $title to Archmage") and it writes them with your library's variables, options and tags, in plain words to review before **Add** or **Apply**. Derivation rules come with warnings when they read a variable nothing sets or test for an option the wildcard doesn't have; constraint rules become matrix cells for tag pairs and exceptions for option pairs, and say when they replace a rule the pair already had, with a **Preview** of each option's chances before and after. **Describe** on every editor's Identity card writes a description and tags (reusing your library's tags), and every AI request now includes the item's name, description and tags so the model knows what it's for. Select modules or bundles in a library list and **Organize with AI** suggests a category, tags to add or remove and a Safe/NSFW rating for each, reusing your categories and tags; click a chip to leave a change out, **Apply** saves with Undo. The **AI** button in the top bar opens a chat: ask about your library and the assistant searches and reads your items to answer, or ask for a change and it proposes it as a card: create a wildcard (with tag groups, negatives, an empty option, a fallback and references to other wildcards, or a vocabulary wildcard with no variable), fixed values, a combine, a derivation, a constraint, a prompt template or a bundle (put in running order, with per-use settings like "pick 2-3", a tag filter, "no empty", "hold" and "internal"); add options or rules; remove, rewrite, retag or re-weight options, set their negatives, the fallback, the empty option's weight or tag groups; replace or remove derivation rules, change a constraint's rules and reach, change fixed values, a combine, a template or a bundle's items; change an item's description, tags, category or rating; or open an editor, a docs page or a Settings section. It can run a stack on the real engine before answering (each variable's top values, options never picked, warnings, sample prompts) and, with its own proposals swapped in, say what they change. In the Test Runner, a bar above the results asks it to **Explain this run**, **Fix the warnings** or say **Why do I never get…** an option. It sees the page you're on: the item in the open editor as it is (unsaved changes included), a list's filters and selection, the Test Runner's last run, the Pack builder's plan. A change to the item open in an editor goes into the editor and Save keeps it; other changes are saved only when you press **Apply** on the card, and **Undo** puts them back. It also answers questions about Wildcard Pipeline from the built-in docs, naming the page it used, and **Ask the assistant** on any docs page explains the page (or the part you selected) in simpler words. **Pack builder** (in the sidebar) makes a whole pack from one description: it plans the wildcards (including vocabulary wildcards other options draw from), fixed values, derivations, combines, constraints and a template, per-use settings for the bundle, and inputs the pack reads but you set through a WP Context Injector, and may ask a few questions; you answer, remove items or type changes; then it builds each item, runs the pack 200 seeds on the engine, rebuilds anything that fails with the problem as a note, and shows sample prompts. **Install** adds everything with a bundle, tagged with the pack's name, says how to wire it on the canvas, and one **Undo** removes it. When an answer is close but not right, type a follow-up ("darker", "keep the first three") and press **Refine**: the model revises its last answer, knowing what you asked before and what you unticked, instead of starting over. **Try again** asks for another take, the arrows flip back to earlier answers, and **Start over** drops the conversation. Each provider keeps its own address, model and key, so switching between them doesn't ask for the key again. The key stays on ComfyUI's side and is never sent back to the browser. The page suggests uncensored local models with Ollama and Hugging Face links, in two groups: fine-tunes trained on creative writing (NSFW included) for drafting, and abliterated models that follow instructions best for organizing and building packs. The assistant sizes itself to your model: **Model size** (automatic from the model's name) gives small models shorter instructions and steadier settings, **Most context to use** makes Ollama load enough context for each request (its small default used to cut the instructions off), and **Test connection** warns when LM Studio or llama.cpp loaded the model with too little context. The chat plans before acting, runs its own proposed module changes on the engine before answering, can propose items that depend on each other in one answer, asks again once when an answer comes back garbled, and is told once to act when it asks "should I go ahead?" or meets your "yes" by asking again. Ask it for a whole new pack and its card's **Plan it** hands the description to the Pack builder and starts the plan. The chat's search reads what items hold (option texts, values, rules), ranks the hits and widens broad subjects, so "what do I have for characters" finds hair, eye and outfit wildcards; replies render bold, lists and code, every item it names is a chip that opens it, prompt syntax is coloured like in the editors ($variables, `{a|b}` picks, `@{…}` references, LoRAs, #tags), and "Tip:" / "Warning:" lines stand out. The **Settings → AI assistant** page now uses the full width: provider buttons marked Local or Cloud, compact fields, and side cards for where your data goes and suggested models. **Most context to use** and **Unload the model after** have presets (4k-128k, right away to 1 hour) with Custom for any number. **Test connection** now warns below 16k of context (it used to stay quiet at 8k, which the chat outgrows after a few turns). The Pack builder reads your library's conventions (tags or sentences, tags, variables, standing negatives), reuses wildcards you already have (marked **yours**), can start from a sample prompt you like, and shows a **Plan review** before building (variables nothing sets, constraint tags neither wildcard lists, loops, picks nothing links), with **Review with AI** and **Fix these in the plan**. Building puts rules after what they read, tells each wildcard which rules use it, retries a failed item with the error, rebuilds one that doesn't fit, and flags options that never come up or take most of the picks. After a wildcard pack import, **Tag and connect with AI** opens the chat to tag the new lists, link them with constraints, bundle them and test the result. No schema change.
- **See what a constraint does before you run it.** The constraint editor has a new **Preview** card: one row per source option, one column per target option, and in each cell the chance that target option is picked, counting the target's weights, the matrix and the exceptions. Ruled-out options show a dash, a row that would leave the target empty says **nothing left**, and **fallback** marks where the target's fallback option stands in.
- **Pick which images go on to the upscaler with WP Image Filter.** Put the new node between your first KSampler and the upscaler. When a run reaches it, a picker opens with every image (grouped by frame when a Context Loop made them). Click the ones you want, click the frame around an image (or **Zoom & refine**, or **Space**) to look closer, and **Enter** to send them on. Only the picked images continue, and their latent, masks, positive and negative conditioning, prompt texts and Context come along with them, so the upscaler gets each image's own prompt. Two **extra** slots carry anything else that should follow the picks. **Keep all** lets everything through and **Stop branch** stops what comes after the node without failing the run. On the node you choose whether it pauses every run, reuses your last picks, or lets everything pass, a timeout, and whether picks keep their batches or go on one image per item. The picker can be tucked away to look at the canvas and keeps your picks until you open it again. While it waits, a short chime plays and the tab title starts with **● Pick images**, so you notice from another tab (new settings: **Image Filter sound**, on by default, and **Image Filter desktop notification**, off by default). No schema change.
- **Refine your picks before they reach the upscaler.** In the Image Filter zoom, a **Refine** panel lets you edit the frame's positive and negative prompt and paint a mask on the image. An edited prompt replaces the text output, and with a CLIP wired into the node's new optional **clip** input the conditioning is re-encoded to match. A painted mask goes to the **masks** output, so an inpainting upscaler can work on just that area.
- **The Image Filter picker knows your Context Loop.** Frames are labelled with the options your sweep pinned (hover for the seed and prompt), a sweep opens as a grid where you choose which wildcards go on rows and columns and the rest split into small grids (click a row, column or group name to pick all of it), **C** compares two images with a slider, **Fit** (**F**) makes a few images fill the picker, **I** adds a Details panel to the zoom (the frame's values, its other images, and each value marked in the prompt), and the picker opens zoomed if you left it zoomed. **Send to Loop** writes your picks back to the loop, locking the kept frames' seeds and bypassing the rest, so the next run repeats only what you liked.

### Fixes

- **Sweep combinations can clear a wildcard's options in one click.** Next to **all** and **enabled only** there is now **none**, so you can untick everything and pick just the few options you want instead of unticking them one by one. A wildcard with nothing ticked sweeps nothing until you tick one.
- **Editing a loop frame goes back to base when that frame goes away.** With frame #5 picked under **edit frame**, lowering the count below 5 or changing the sweep left you editing a frame that no longer existed (or now meant a different combination). It now switches back to **base**.
- **Frame locks and bypasses no longer come back on the wrong frame.** Lowering a Context Loop's count used to keep the seed locks and bypasses of the frames past it, and raising the count again brought them back. Now they are dropped. Changing a sweep moves each lock and bypass with its combination, or drops it when that combination no longer runs.
- **The loop's count is locked while a sweep is on.** The sweep decides how many frames run, so the count field now greys out and shows the sweep's frame count instead of looking editable.
