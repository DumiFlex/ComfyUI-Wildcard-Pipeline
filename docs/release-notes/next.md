### New

- **WP Slider: several number sliders in one node.** Each slider sits on its own row and writes `$its_variable`: the number (with the decimals you pick), a text of your own that can read the number (`(intricate details:$detail.num)`), or the word of the range the number is in (close-up up to 0.3, medium shot up to 0.7, wide shot past that), each word with its own negative. A slider can also show an INT or FLOAT output at the right of its row for steps, cfg or a LoRA strength. The sliders are part of the node, so they work in Nodes 2.0, where canvas-drawn sliders don't. Each slider picks a style (a row with a thin track, a filled bar with the name inside, or an upright fader; neighbouring faders stand side by side like a mixing desk) and whether a drag snaps to the step (hold Shift for finer values either way). Edit view, labels, icons and colours work as in WP Toggles.
- **WP Slider 2D: one XY pad, two numbers.** Drag a point to set two numbers at once, X across and Y up: a picture's width and height (with Area on, the shaded box looks like the picture), cfg and steps, or a mood from calm to wild and dark to bright. Each axis works like a WP Slider slider (its own variable, Number / Text / Words, `$name.num`, negative) and has its own INT or FLOAT output, `x` and `y`. Four styles: Pad; Size (shaded box, 1:1 / 4:3 / 16:9 guide lines and a W × H readout); Stick (round, zero in the middle); Map (a Words axis's words written on the pad, each section in its own soft colour). Dots sit on every step, Snap to dots lands the point on one, the shape can follow the two ranges (Auto), the pad comes in S / M / L, and Swap trades the axes.
- **WP Slider 3D: three numbers, or a camera round the subject.** The pad styles are the 2D pad with a Z fader beside it (a ring round the point shows Z, the mouse wheel moves it). The Orbit style puts a camera or a light round the subject: drag round it for the side and the distance, up the arc for the height. Its Camera words write `$view` = "front-left view, high angle, medium shot" (ready for a prompt or a multi-angle LoRA); its Light words write `$light` = "rim light from the back-left, high light, soft light". The words are ordinary Words ranges, so you can rename or add any, and the phrase is a Text value you can reword. The Mix style is a triangle with one thing at each corner: drag the point to blend three styles, moods or LoRAs, and the three shares always add up to 100% (its style example writes `$style_mix` = "(watercolor:0.40), (ink sketch:0.30), (oil painting:0.30)"). Outputs `x`, `y` and `z`.
- **`$name.num` reads a slider's number** whatever its variable holds, in templates, derivations and other texts, like `$name.bool` for a toggle. A pack that uses it is stamped schema 13, so a Wildcard Pipeline that doesn't know it refuses it with a message instead of printing it wrong.
- **New node: WP Seeds.** Name the seeds your workflow needs (Hero, Background, Sampler …) in one node. Each row follows the node's base seed (or the Loop's, with From Loop on), rolls its own after every queue, or stays fixed, and gets its own seed per frame of a Context Loop, with a lock for any frame. Buttons on each row cycle its mode and bring back the seed it ran with last time. Pinned rows give INT outputs for samplers. The Seeds window edits the rows and shows every row × frame in a grid.
- **WP Context: Seed from.** With a Loop or WP Seeds upstream, a chip next to the node's name picks the seed it runs on: Auto (as before), Loop, Own seed (the widget or its wire, even while the Loop overrides) or a WP Seeds row. Nothing takes over on its own any more just because it is wired.
- **Constraints now look ahead at a narrowed target.** When a constraint's target is narrowed before it rolls (a locked pick, Match variable, a Pool filter such as place chips on WP Toggles, the node's option toggles, or a weight of 0), its source only picks options something left in the target accepts. Lock the place to a bed, or tick only the Bathroom chip, and the pose follows. Works down chains (mood → pose → place) and with every reach setting; a seed-locked source rolls inside what fits, a value-locked one is never changed (WP Debug warns on a clash). WP Debug marks the dropped options "doesn't fit $place". A target nothing narrows changes nothing, so those runs roll as before.
- **The row lock can lock the value too.** Click a row's lock once to lock its seed, as before; on a wildcard, click again to lock the value: it always takes the option it picked last run, whatever the seed, and constraints above it keep their source fitting that option. A third click unlocks. A value-locked row shows its option next to its name, its editor has a Locked value switch, and with a loop frame open the lock applies to that frame only. The value step needs one run first; until then the second click unlocks.
- **WP Toggles: click a mute / bypass icon to see what it drives.** The canvas glides to the wired node or canvas group. A toggle that drives several (the nodes of a WP Node Group, or the canvas groups it picks) opens a list instead: All targets frames them together, or pick one. The Bookmarks dock's Back returns to where you were.
- **WP Toggles can lock rows of WP Context nodes.** Set a toggle's When on to Lock seed or Lock value and pick rows from any WP Context on the canvas (by its codename, title and row; no wires). Switching the toggle on locks them to what the last run did, frame by frame on a loop; switching it off unlocks only the rows it locked, never ones you locked by hand. A row or node that is gone shows red on the toggle, puts a badge on the node with a Remove missing targets button, and gets a warning when you queue.
- **Constraints look ahead through rules too.** When a rule between a wildcard and a narrowed target sets what the target's filter or Match variable reads from that wildcard's pick, the wildcard now tries each of its options and keeps the ones that lead somewhere the target can follow. This also covers a chain with no constraint from the wildcard itself: the pose sets `$pose_need` through a rule, a mirror wildcard matches it, and a constraint from the mirror rules the place. Lock the place to a bed (or tick only beds) and the pose picks one that needs a bed. Before, this case only gave a "can't keep to what it allows" warning, which now shows only past 32 different options.
- **Match variable sees through references.** An option with a reference matches the variable as the editor shows it, so `$want` = "red @Hat" picks "red @Hat". An option that is only a reference (`@Places`) matches when one of Places' options does, and then takes that option: `$want` = "forest" gives forest. WP Debug says "inside its ref" when it matched that way.
- **Lock value works on multi-pick rows.** The row lock's second click on a wildcard that picks several options (Pick 2–3 and the like) now locks all of them, in the order the last run had them: the row shows "= hat, scarf", WP Toggles' Lock value does the same, and constraints above it keep their source fitting every locked pick. Before, a multi-pick row could only lock its seed.
- **Constraints look ahead into the next WP Context nodes.** A target locked, filtered or toggled down in a later WP Context (down a straight line of WP nodes, up to four Contexts) now keeps its source in this node fitting, as one in the same node always did. Lock the place in the second Context and the pose in the first follows.
- **A "set later" warning when a wildcard reads a variable too early.** When a row's Category filter `$variable` or Match variable is set only by a row further down the same WP Context, the row now shows a "set later" chip: the variable is still empty when it rolls, so the filter or match does nothing. Move the row that sets it above.

- **WP Image Filter: quicker picking.** Values has a search box and can hide on/off switches; while comparing two images it lists what differs between them first. The countdown has an Add time menu (+1, +5, +10 or +30 min), and the node waits that much longer. Grid's **Picked only** hides what you left out, and **Same in every frame** (or Detail's **Image N in every frame**) picks the 1st, 2nd … image of every frame at once. The mouse wheel steps images in Detail.

### Fixes

- **WP Toggles' mute / bypass icon sits on the chip's middle in grid tiles** instead of riding up to the top of the tile.
- **WP Image Filter's Values and prompt marks no longer miss variables in a big workflow.** The picker got only a frame's first 80 variables, so in a workflow that sets many (WP Parts sets about 170, mostly switches) $subject and other late ones were left out of Values and unmarked in the prompt. Variables the prompt uses now come first, up to 200, and a value a prompt cleaner reordered or trimmed is marked piece by piece. In Detail, a click in the clear space beside the picture steps to the previous (left half) or next (right half) image.
- **A Pool filter with several `$variables` stops filling WP Debug with notes.** With one term per toggle chip (`$pick_home, $pick_beach, …`), an unset chip is expected: once another term narrowed, the unset ones no longer leave a "Filter variable left out" note.
- **WP Image Filter handles a run of mixed image sizes.** Grid gives every tile the shape most images share and fits the others inside it, so rows and labels line up and Fit no longer overflows; each tile says its size when sizes differ. Detail scales every image to fill the same space (a 512 draft as big as a 1536 upscale), so stepping never moves the buttons or the strip. In Zoom the next image swaps in only once it has loaded, never stretched into the last one's box, and a zoomed view keeps the spot the same size on screen. The node now sends each image's size, so the picker lays it out before the images load. The picker's header has one close button again: the × tucks it away from any mode (the run keeps waiting), Esc still steps back a mode.
- **WP Note and WP Bookmark show no node card behind them on ComfyUI frontend 1.58.** Nodes 2.0 on 1.58 moved the card's background and shadow, so a grey frame, a shadow and the "Wildcard-Pipeline" badge showed around the panel and it sat a few pixels low. Both frontends now draw just the panel.
- **The Bookmarks dock opens, closes and edits at once, and jumps start right away.** To find free screen space, the dock scanned the screen edges with hundreds of hit tests on every open, close and jump. On a big Nodes 2.0 graph in a Chromium browser (Chrome, Edge, EZi Desktop) that took about 3 seconds. It now does far fewer, reuses the result while the layout stays the same, and refreshes it while the browser is idle.
- **Big Nodes 2.0 graphs go idle again.** The input dot WP Prompt Assembler lines up with its template field could flip between two spots a third of a pixel apart, which re-measured the node on every frame and kept the canvas busy. Moves under a pixel are now ignored, for WP Toggles' output dots too.
- **Jumping to a bookmark glides more smoothly.** The move is timed from its first frame, eases in and out more softly, and takes a little longer for a longer trip (0.26 to 0.52 s). In Nodes 2.0 the node layer is held while it moves, the way ComfyUI does when you pan by hand, so it no longer redraws every node at each zoom step.
- **No more "deprecated" warnings from WP nodes in the console on ComfyUI frontend 1.58.** WP nodes read an input's link and an output's links the new way, so 1.58 no longer logs a warning and rebuilds the link list on every check while you edit a graph.
